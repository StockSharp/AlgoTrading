# Примеры алгоритмической торговли StockSharp

[English](README.md) | [中文](README_zh.md) | [Español](README_es.md) | [Deutsch](README_de.md) | [Português](README_pt.md) | [日本語](README_ja.md)

Это официальный репозиторий StockSharp с примерами алгоритмической торговли. Здесь объединены большой упорядоченный каталог стратегий для API, визуальные примеры для «Дизайнера стратегий», учебные материалы и автоматические проверки, которые поддерживают примеры в рабочем состоянии.

Репозиторий предназначен для обучения, исследований, создания прототипов и регрессионного тестирования. Стратегии демонстрируют торговые идеи и возможности API StockSharp, но не являются готовыми инвестиционными рекомендациями.

## Содержимое репозитория

### Каталог стратегий API

В каталоге [`API`](API/) представлены как классические подходы — пересечения скользящих средних, пробои, моментум, торговля волатильностью и возврат к среднему, — так и парный трейдинг, арбитраж, маркет-мейкинг, портфельные методы, модели потока заявок, эксперименты с машинным обучением и множество специализированных вариаций.

В каталоге стратегии сгруппированы по основной торговой идее. На диске они распределены по нумерованным диапазонам, чтобы GitHub мог эффективно отображать большую коллекцию. Типичный пример устроен так:

```text
API/0001-0100/0001_MA_CrossOver/
├── CS/
│   ├── MaCrossoverStrategy.cs
│   └── logo.svg
├── PY/
│   ├── ma_crossover_strategy.py
│   └── logo.svg
├── README.md
├── README_ru.md
├── README_zh.md
├── README_es.md
├── README_de.md
├── README_pt.md
└── README_ja.md
```

Для каждого примера одна и та же торговая идея реализована на C# и Python. Документация на семи языках описывает принцип работы, параметры, логику сигналов и риски. Прозрачные SVG-логотипы обозначают стратегию и язык реализации и остаются читаемыми в светлой и тёмной темах.

### Примеры для «Дизайнера стратегий»

Каталог [`Designer`](Designer/) содержит визуальные схемы, переиспользуемые типы стратегий и учебные примеры для [«Дизайнера стратегий» StockSharp](https://doc.stocksharp.com/topics/designer.html). Они полезны, если удобнее собирать и анализировать стратегию графически, а не начинать с исходного кода.

### Средства сборки и тестирования

В репозитории есть два небольших проекта .NET:

- [`Backtester`](Backtester/) динамически компилирует выбранную стратегию на C# и запускает её на встроенной тестовой истории.
- [`Tests`](Tests/) компилирует примеры API и проверяет их в среде исторической эмуляции StockSharp.

Тестовый проект использует генератор исходного кода, поэтому для обычной стратегии не требуется вручную добавлять тестовый метод. Каждый сгенерированный тест запускает стратегию на тестовых рыночных данных, проверяет создание заявок и сделок, а также клонирование и сериализацию настроек. Для стратегий с несколькими инструментами или нестандартной подготовкой предусмотрены явные переопределения в тестовом проекте.

Перед сборкой .NET скрипт [`Tools/validate_api_structure.py`](Tools/validate_api_structure.py) выполняет быстрые структурные проверки: правильность нумерованных каталогов, паритет C# и Python, наличие обязательных переводов и исходных файлов, а также отсутствие устаревших утверждений о недоступности одной из языковых версий.

## Требования

Для полной локальной сборки потребуются:

- .NET 10 SDK;
- Python 3 для структурного валидатора;
- соседняя копия репозитория платформы StockSharp.

Ссылки на проекты рассчитаны на следующую структуру каталогов:

```text
<workspace>/
├── AlgoTrading/
└── StockSharp (GitHub)/
```

Клонируйте этот репозиторий в каталог `AlgoTrading`, а [репозиторий платформы StockSharp](https://github.com/StockSharp/StockSharp) — в каталог `StockSharp (GitHub)` с тем же родительским каталогом.

## Проверка, сборка и тесты

Сначала запустите быструю проверку структуры:

```bash
python Tools/validate_api_structure.py
```

Затем соберите и протестируйте решение в той же конфигурации, которую использует CI:

```bash
dotnet build AlgoTrading.slnx --configuration Release
dotnet test AlgoTrading.slnx --no-build --configuration Release
```

Чтобы запустить только один сгенерированный тест, используйте имя каталога стратегии в формате PascalCase. Например:

```bash
dotnet test Tests/Tests.csproj --no-build --configuration Release \
  --filter "FullyQualifiedName~MaCrossover"
```

Для прямой компиляции и тестирования одного примера на C#:

```bash
dotnet run --project Backtester/Backtester.csproj -- \
  API/0001-0100/0001_MA_CrossOver/CS/MaCrossoverStrategy.cs
```

## Использование примеров

Выберите стратегию в [каталоге](API/README_ru.md), изучите её предположения и параметры, затем сравните реализации на C# и Python. Рассматривайте каждый пример как отправную точку: перед оценкой идеи задайте подходящие рыночные данные, комиссии, проскальзывание, задержки, правила управления позицией и лимиты риска.

Для визуальной разработки установите [«Дизайнер стратегий»](https://stocksharp.com/store/strategy-designer/), откройте встроенную [галерею стратегий](https://doc.stocksharp.com/topics/designer/strategy_gallery.html) и используйте схемы из каталога [`Designer`](Designer/) как учебные материалы или прототипы.

Любую изменённую стратегию следует проверять на данных вне обучающей выборки и в режиме симуляции до рассмотрения реальной торговли. Бэктест показывает поведение на конкретном наборе данных, но не доказывает будущую прибыльность.

## Участие в разработке

Приветствуются изменения, повышающие корректность, понятность, полноту или учебную ценность примеров. При добавлении или изменении стратегии API:

1. Размещайте стратегию в соответствующем нумерованном диапазоне.
2. Поддерживайте реализации и на C#, и на Python.
3. Синхронизируйте семь локализованных README с фактическими параметрами и поведением стратегии.
4. Обновляйте прозрачные SVG-логотипы для каждого языка реализации, если меняется образ стратегии.
5. Перед созданием pull request запускайте валидатор структуры, сборку Release и относящиеся к изменению тесты.

Обычные стратегии обнаруживаются генератором тестов автоматически. Ручное переопределение требуется только тогда, когда примеру нужны специальные инструменты, портфели, рыночные данные или другая подготовка, недоступная стандартному стенду.
