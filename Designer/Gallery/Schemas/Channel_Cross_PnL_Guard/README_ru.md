# Схема стратегии пересечения канала с защитой по P&L
[English](README.md) | [中文](README_zh.md) | [Español](README_es.md) | [Deutsch](README_de.md) | [Português](README_pt.md) | [日本語](README_ja.md)

Эта схема рассчитывает середину канала за 24 свечи по завершённым пятиминутным свечам BTCUSDT@BNBFT и торгует точные пересечения закрытия и середины после паузы в 200 свечей. Стакан TONUSDT@BNBFT подтверждает готовность потока и задаёт моменты проверки нереализованного P&L; однократная денежная защита запрашивает отмену заявок входа, если они ещё активны, и закрывает позицию BTC при достижении любого заданного порога.

## Обзор стратегии

- Переменная BTC Security настраивает подписку на завершённые пятиминутные свечи. Рыночные заявки, исполнения, закрытие позиции и P&L относятся к выбранному Strategy Security, который нужно задать как BTCUSDT@BNBFT в соответствии с BTC Security.
- Highest(24) получает свечи BTC и отслеживает их максимумы, а Lowest(24) — минимумы. Арифметическая середина равна `(Highest + Lowest) / 2`; первое доступное решение сохраняет закрытие и середину, запускает начальную паузу и не отправляет заявку.
- Пересечение вверх требует `Previous Close <= Previous Midpoint` и `Current Close > Current Midpoint`. Пересечение вниз требует `Previous Close >= Previous Midpoint` и `Current Close < Current Midpoint`. Сохранённые значения обновляются на каждой завершённой свече BTC, в том числе когда пауза запрещает действие.
- Вход или разворот разрешён только после 200 строго последующих завершённых свечей BTC и хотя бы одного события стакана TON. Каждое принятое пересечение перезапускает задержку на 200 свечей до отправки рыночной заявки.
- Знаковый фиксатор, обновляемый исполнениями, хранит управляемое состояние BTC: `-1` — шорт, `0` — флэт, `1` — лонг. Нереализованный P&L не ниже `500` или не выше `-300` запускает однократную защиту; следующее исполнение покупки или продажи снова ставит её на взвод.

## Правила входа и выхода

- **Вход в лонг**: Когда возникает точное пересечение вверх, знаковый фиксатор находится во флэте или шорте, оба допуска готовы и пауза завершена, отправляется рыночная заявка на покупку. Вход из флэта использует Base BTC Volume, а разворот из шорта в лонг — удвоенный объём.
- **Вход в шорт**: Когда возникает точное пересечение вниз, знаковый фиксатор находится во флэте или лонге, оба допуска готовы и пауза завершена, отправляется рыночная заявка на продажу. Вход из флэта использует Base BTC Volume, а разворот из лонга в шорт — удвоенный объём.
- **Выход**: Допустимое противоположное пересечение выполняет обычный одношаговый разворот, а не отдельное закрытие. Независимо от него защита по P&L срабатывает при `P&L >= Profit Target` или `P&L <= -abs(Maximum Loss)`, отправляет команду массовой отмены и адресные запросы отмены для сохранённых заявок входа, затем запрашивает рыночное закрытие. Такое денежное закрытие не перезапускает паузу между пересечениями.

## Параметры

| Параметр | По умолчанию | Описание |
|---|---|---|
| BTC Security | BTCUSDT@BNBFT | Инструмент подписки на пятиминутные свечи. Задайте Strategy Security тем же значением, поскольку торговые действия, исполнения, закрытие позиции и P&L используют Strategy Security. |
| TON Readiness Security | TONUSDT@BNBFT | Инструмент только для подписки на стакан, которая открывает допуск готовности потока и задаёт моменты выборки P&L; цены котировок не используются для заявок BTC или оценки P&L. |
| Candle Series | 00:05:00 | Серия завершённых пятиминутных свечей BTCUSDT для канала, точных пересечений, подсчёта паузы и графика. |
| Highest Length | 24 | Число свечей BTC, по которым Highest рассчитывает верхнюю границу канала. |
| Lowest Length | 24 | Число свечей BTC, по которым Lowest рассчитывает нижнюю границу канала. |
| Base BTC Volume | 1 | Базовый объём рыночного входа. Формула действия — `Base BTC Volume * (1 + abs(latch))`, поэтому вход из флэта использует базовый объём, а разворот — удвоенный. |
| Cooldown N | 200 | Число строго последующих завершённых свечей BTC, требуемых после инициализации или принятого пересечения, прежде чем другое пересечение сможет отправить заявку. |
| Profit Target | 500 | Уровень нереализованного P&L, при достижении или превышении которого однократная защита запрашивает отмену и рыночное закрытие. |
| Maximum Loss | 300 | Положительная величина убытка; порог защиты рассчитывается как `-abs(Maximum Loss)`, по умолчанию это `-300`. |

## Детали диаграммы

- [Переменная](https://doc.stocksharp.com/ru/topics/designer/strategies/using_visual_designer/elements/data_sources/variable.html) BTC передаёт значение только в подписку на завершённые [Свечи](https://doc.stocksharp.com/ru/topics/designer/strategies/using_visual_designer/elements/data_sources/candles.html). Переменная TON подключена только к [Стакану](https://doc.stocksharp.com/ru/topics/designer/strategies/using_visual_designer/elements/market_depths/order_book.html): первое событие записывает готовность, а последующие также задают моменты выборки последнего нереализованного P&L.
- Два кубика [Индикатор](https://doc.stocksharp.com/ru/topics/designer/strategies/using_visual_designer/elements/common/indicator.html) получают каждую свечу BTC. Highest(24), Lowest(24), формула середины, фиксаторы текущих и предыдущих значений сохраняют одно полное решение по закрытию и каналу на завершённую свечу.
- Кубик Delay запускается при первом решении и перезапускается при каждом принятом пересечении. Поскольку текущая свеча поступает на его вход до выполнения ветви решения, допуск возвращается только через 200 последующих завершённых свечей BTC; отклонённые пересечения всё равно заменяют сохранённые закрытие и середину.
- Кубики [Регистрация заявки](https://doc.stocksharp.com/ru/topics/designer/strategies/using_visual_designer/elements/orders/register.html) для покупки и продажи отправляют рыночные заявки объёмом `Base BTC Volume * (1 + abs(latch))`. Их выходы MyTrade записывают знаковое состояние и заново взводят защиту по P&L по фактическим исполнениям.
- События изменения P&L и события стакана TON выбирают последнее значение нереализованного P&L. Строгие сравнения порогов входят в общий взведённый допуск, поэтому достижение `500` или `-300` может породить только одно защитное действие до следующего исполнения входа.
- Защита вызывает [Массовую отмену заявок](https://doc.stocksharp.com/ru/topics/designer/strategies/using_visual_designer/elements/orders/mass_cancel.html), передаёт сохранённые ссылки Order покупки и продажи кубикам адресной отмены и использует Base BTC Volume для рыночного закрытия текущей экспозиции BTC. График получает свечи BTC, Highest(24), Lowest(24), середину, P&L, отправленные заявки и все исполнения стратегии.

## Использование

Импортируйте файл `.json` в Designer, задайте Strategy Security как BTCUSDT@BNBFT, запустите схему в тестере с историей свечей и стакана, затем настройте параметры или кубики под свой инструмент перед торговлей в реальном времени.
