# Схема стратегии пробоя после стабилизации заявки
[English](README.md) | [中文](README_zh.md) | [Español](README_es.md) | [Deutsch](README_de.md) | [Português](README_pt.md) | [日本語](README_ja.md)

Эта схема отслеживает завершённые пятиминутные свечи BTCUSDT@BNBFT и ищет переход от тела, стабилизированного ниже половины ATR(14), к телу, расширившемуся выше этого уровня. Она размещает одну лимитную заявку по цене закрытия сигнальной свечи, отводит ей три последующие свечи для завершения и удваивает базовый объём при исполненном развороте.

![schema](schema.svg)

## Обзор стратегии

- Завершённые пятиминутные свечи предоставляют цены Open и Close, а сформированные значения ATR(14) задают текущий масштаб волатильности.
- Body вычисляется как `abs(Close - Open)`, а граница стабилизации — как `ATR * Stabilization Factor`. Значение коэффициента по умолчанию равно `0.5`.
- Первая сформированная пара Body/ATR инициализирует сохранённые предыдущие значения без создания сигнала. Каждая следующая сформированная пара сопоставляет предыдущее и текущее тело с соответствующей границей.
- Для сетапа нужны `Previous Body < Previous ATR * 0.5` и `Current Body > Current ATR * 0.5`. Равенство любой границе условию не соответствует.
- Общий фиксатор ожидающей заявки допускает только одну активную лимитную заявку. Отдельные ограничители срока Buy и Sell не позволяют стороне повторно использовать свой трёхсвечной таймер до его завершения.

## Правила входа и выхода

- **Длинный вход**: Когда подходящая свеча расширения является бычьей (`Close > Open`), знаковое состояние равно нулю или указывает на короткую позицию, ожидающей заявки нет и ограничитель срока Buy готов, отправляется лимитная покупка по текущему Close.
- **Короткий вход**: Когда подходящая свеча расширения является медвежьей (`Close < Open`), знаковое состояние равно нулю или указывает на длинную позицию, ожидающей заявки нет и ограничитель срока Sell готов, отправляется лимитная продажа по текущему Close.
- **Объём заявки**: Объём равен `Base Volume * (1 + abs(state))`. Вход из нулевого состояния использует одну базовую единицу, а разрешённый разворот из `-1` или `1` — две.
- **Выход**: Ценовой защиты нет. Экспозиция меняется только при исполнении встречной лимитной заявки; для неисполненной заявки после трёх строго последующих завершённых свечей отправляется адресный запрос отмены.

## Параметры

| Параметр | По умолчанию | Описание |
|---|---|---|
| Security | BTCUSDT@BNBFT | Инструмент для подписки на завершённые пятиминутные свечи. Для Strategy Security нужно задать то же значение, поскольку заявки, отмены и исполнения используют Strategy Security и Strategy Portfolio. |
| Candle Series | 00:05:00 | Завершённые пятиминутные свечи для ATR, расчёта тела, сигналов, отсчёта срока и графика. |
| ATR Length | 14 | Период усреднения Average True Range. Решения начинаются только после формирования ATR. |
| Stabilization Factor | 0.5 | Множитель, отдельно применяемый к предыдущему и текущему ATR для получения границ тела. |
| Lifetime N | 3 | Число строго последующих завершённых свечей до запроса отмены неисполненной лимитной заявки. |
| Base Volume | 1 | Объём входа из нулевого состояния; формула действия удваивает его для разворота. |

## Детали диаграммы

- [Variable](https://doc.stocksharp.com/en/topics/designer/strategies/using_visual_designer/elements/data_sources/variable.html) Security настраивает только подписку [Candles](https://doc.stocksharp.com/en/topics/designer/strategies/using_visual_designer/elements/data_sources/candles.html) на завершённые свечи. Каждая завершённая свеча предоставляет Open, Close и полный объект свечи для ATR; блоки заявок и исполнений используют Strategy Security и Strategy Portfolio, поэтому Strategy Security должен совпадать с Security.
- Блок [Indicator](https://doc.stocksharp.com/en/topics/designer/strategies/using_visual_designer/elements/common/indicator.html) выдаёт только сформированные значения ATR(14). Формулы и фиксаторы согласуют текущие Body и границу, предыдущие Body и границу внутри одного решения по свече.
- Фиксатор инициализации подавляет первое сформированное решение и сохраняет его пару. Последующие решения проверяют два строгих отношения к границам до обновления фиксаторов предыдущих значений.
- Текущая свеча поступает в оба счётчика срока до выполнения сигнальной ветви. Запуск счётчика после этого входа приводит к срабатыванию на третьей более поздней завершённой свече, поэтому сигнальная свеча не входит в собственный срок.
- Принятый сетап закрывает ограничитель таймера своей стороны и устанавливает общий фиксатор ожидания до запуска [Order registering](https://doc.stocksharp.com/en/topics/designer/strategies/using_visual_designer/elements/orders/register.html). Общий фиксатор очищается только после сообщения о финальном состоянии заявки; таймер стороны остаётся недоступным до выхода через три свечи, даже если заявка исполнилась раньше.
- Каждый блок регистрации сохраняет ссылку Order для адресной отмены. Выход счётчика срока передаёт соответствующую сохранённую ссылку в отмену и вновь открывает только ограничитель таймера этой стороны.
- События MyTrade задают знаковое состояние по фактическим исполнениям: продажа устанавливает `-1`, покупка — `1`, а начальное значение `0` означает отсутствие позиции. На график поступают свечи, ATR, Body, граница стабилизации, отправленные заявки и исполнения стратегии.

## Использование

Импортируйте файл `.json` в Designer, задайте для Strategy Security значение BTCUSDT@BNBFT, запустите схему на пятиминутной истории и проверьте исполнения и отмены лимитных заявок перед настройкой коэффициента, срока или объёма для другой торговой среды.
