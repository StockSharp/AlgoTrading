# F-Score Reversal

## Правила торговли

При месячном пересмотре вычислить доходность за Lookback дней: P[d] / P[d−Lookback] − 1. Среди опубликованных FScore >= FHi купить худшую доходность; при IsShortEnabled среди FScore <= FLo продать лучшую. Границы включены, FHi должен превышать FLo. Используются опубликованные оценки Piotroski — целые 0..9, с последним известным периодом/редакцией и ограничением MaxReportAgeDays. Каждой выбранной стороне выделяется половина общего бюджета; отсутствующая или выключенная сторона остаётся деньгами. Перед новыми месячными входами полностью закрыть старый портфель и дождаться исполнений.

Обрабатываются только синхронизированные завершённые свечи. Для статистики считаются разные даты UTC; новая внутридневная свеча заменяет цену той же даты. Ребалансировка выполняется один раз на первой подходящей общей свече месяца; непрогретые данные откладывают решение. Равные оценки упорядочиваются по Security.Id.

Все наблюдения должны быть опубликованы к закрытию сигнальной свечи. При внутридневном исполнении дневные цены берутся строго до текущей UTC-даты; завершённая дневная свеча учитывает собственную завершённую дату. Будущие CSV-даты не прогревают решение.

Граница доступности публикаций — последний фактический CloseTime среди синхронизированных завершённых свечей. Торговая сессия может закончиться раньше полного заданного интервала свечи.

## Входные данные

PriceHistoryFile — необязательный CSV положительных дневных цен: SecurityId,Date,Close. Дата имеет формат yyyy-MM-dd. Текущие и будущие даты не прогревают решение заранее; завершённые свечи заменяют цену своей даты UTC. Повторы дат запрещены. Файл позволяет прогреть длинный период при коротком архиве исполнения.

FScoreFile — обязательный CSV: `SecurityId,PeriodEnd,PublishedAt,FScore`. PeriodEnd — `yyyy-MM-dd`, PublishedAt — UTC `yyyy-MM-ddTHH:mm:ssZ`. Отклоняются оценки вне целых 0..9, дубли редакций и публикации до PeriodEnd. Выбирается новейший финансовый период и его последняя опубликованная редакция; MaxReportAgeDays считается от PeriodEnd.

## Исполнение

Universe задаётся явно. Цены и Capital выражены в USD: одна единица цены соответствует одной торгуемой единице. Capital — фиксированный бюджет; Leverage задаёт валовую экспозицию. Стоп-лосс и тейк-профит не добавляются.

Округлять целевые количества к нулю по VolumeStep. Перед новыми позициями дождаться фактических исполнений полного закрытия; сверяться с реальными позициями, соблюдать MinVolume/MaxVolume и разбивать крупные корректировки между следующими свечами. MinTradeUsd фильтрует корректировки ненулевых целей; полное закрытие обходит этот порог.

## Проверка

Оба языка проверяются на исполнениях из имеющегося BTC/TON-архива с явными фикстурами ставок, финансовых отчётов, оценок, текстов и прогрева. Календарные фикстуры переносят даты архивных OHLC/объёмов и задают котировки исполнения; это не многолетняя рыночная история. Проверяются независимые формулы, направление/объём заявок, фактические сделки, остатки позиций и запрещённые даты решений. Два бакета, K=1 и AssetDecile=1 — явные профили механики, а не доказательство работы полного торгового универсума. Доходность не заявляется.
