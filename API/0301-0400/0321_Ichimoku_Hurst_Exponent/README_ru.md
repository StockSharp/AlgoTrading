# Ишимоку и показатель Херста
[English](README.md) | [中文](README_zh.md) | [Español](README_es.md) | [Deutsch](README_de.md) | [Português](README_pt.md) | [日本語](README_ja.md)

Трендовая стратегия объединяет пересечения Tenkan/Kijun, облако Ишимоку и фильтр Херста по логарифмическим доходностям. Сигналы рассчитываются по завершённым свечам.

## Расчёт

Tenkan и Kijun равны `(максимальный High + минимальный Low) / 2` за соответствующий период. Несмещённая Senkou A — их среднее, Senkou B — середина диапазона за `SenkouSpanBPeriod`. Используются причинные смещённые линии встроенного StockSharp Ichimoku со сдвигом `KijunPeriod` и его буфером инициализации; будущие свечи не читаются.

Для последних `HurstPeriod` закрытий вычисляются `n = HurstPeriod - 1` доходностей `r[i] = ln(C[i] / C[i-1])`. Пусть `mu` — их среднее, `X[k] = sum(r[i] - mu)`, `R = max(X) - min(X)`, а `S` — стандартное отклонение с делением на `n`. Фильтр `H = ln(R / S) / ln(n)` рассчитывает StockSharp HurstExponent по этим доходностям. История накапливается с первой завершённой свечи. Нужны как минимум одиннадцать закрытий, полное окно и ненулевая дисперсия. Неположительное закрытие запускает накопление окна заново; отсутствие значения Херста запрещает вход.

## Торговля

- **Лонг:** позиции нет, закрытие строго выше обеих границ облака, Tenkan пересекает Kijun из `<=` в `>`, `H > HurstThreshold`, ATR сформирован и положителен, ожидание завершено.
- **Шорт:** позиции нет, закрытие строго ниже обеих границ, Tenkan пересекает Kijun в обратном направлении; действуют те же условия Херста, ATR и ожидания.
- **Сигнальный выход:** весь лонг закрывается при закрытии ниже обеих границ либо пересечении Tenkan вниз; весь шорт — при симметричных условиях. Выходы действуют во время ожидания и не требуют прохождения фильтра Херста.
- **Заявки:** рыночный вход объёмом `Volume`, выход — на фактический остаток позиции. Незавершённая заявка блокирует следующую сигнальную заявку. Сначала позиция закрывается, затем возможен новый вход.
- **Ожидание:** каждая сигнальная заявка запускает `SignalCooldownBars` заново; следующий вход разрешён через это число завершённых свечей.

## Защита

ATR Уайлдера использует `AtrPeriod`. Для каждого входа фиксируется расстояние `StopLossAtr * ATR` по сигнальной свече; уровень отсчитывается от фактической цены исполнения входа. Локальная защита обрабатывает Level1 и закрывает позицию рыночной заявкой между сигнальными свечами. Последующие изменения ATR расстояние не меняют. `StopLossAtr = 0` отключает защиту на запуск. Тейк-профита и трейлинга нет.

## Параметры по умолчанию

| Параметр | Значение |
|---|---|
| `TenkanPeriod` | 9 |
| `KijunPeriod` | 26 |
| `SenkouSpanBPeriod` | 52 |
| `HurstPeriod` | 100 закрытий |
| `HurstThreshold` | 0.5 |
| `SignalCooldownBars` | 6 |
| `AtrPeriod` | 14 |
| `StopLossAtr` | 2 |
| `CandleType` | 15 минут |

Тесты сверяют каждую сигнальную заявку и исполнения с независимым расчётом облака и R/S по доходностям на имеющемся BTC/TON-архиве. Отдельно проверяются прогрев Херста, фиксированное расстояние ATR и реальные исполнения защитных выходов внутри свечи.

Для сравнения защиты на архиве используются периоды Tenkan/Kijun/Senkou B 15/40/70 и HurstThreshold 0.45: они позволяют проверить срабатывание штатного расстояния 2 × ATR. Сигналы исходных периодов 9/26/52 проверяются отдельно. В проверках защиты объём входа равен 3.
