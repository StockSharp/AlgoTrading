# Стратегия Frank Ud (минимальная версия)
[English](README.md) | [中文](README_zh.md) | [Español](README_es.md) | [Deutsch](README_de.md) | [Português](README_pt.md) | [日本語](README_ja.md)

Пример демонстрирует портирование классического советника **Frank Ud** из MetaTrader в StockSharp на основе высокоуровневого API. Оригинальный MQL-скрипт ведёт две хеджирующие сетки (лонгов и шортов), наращивая позицию при движении цены против последнего входа. Как только самый свежий (и самый крупный) ордер приносит фиксированное число пунктов, все сделки данного направления закрываются единовременно.

## Основные идеи

1. **Симметричное хеджирование.** Стратегия параллельно ведёт «лестницы» длинных и коротких позиций, поэтому может держать лонги и шорты одновременно, как и в режиме хеджирования MetaTrader.
2. **Мартингейл.** Первый ордер на каждой стороне использует `InitialVolume` (по умолчанию 0.1 лота). Каждый следующий вход удваивает наибольший уже открытый объём. Любой отправляемый объём — включая самый первый — приводится к тому, что инструмент действительно принимает: округляется вниз до целого числа шагов `VolumeStep`, поднимается до `MinVolume`, если оказался меньше, и ограничивается сверху `MaxVolume`. Ограничения, которые инструмент не сообщает, пропускаются.
3. **Шаг сетки.** Добавление нового ордера допускается только после смещения цены минимум на `ReEntryPips` (41 пункт) относительно лучшей цены текущей лестницы. Для лонгов требуется падение ask ниже `минимальная_цена_покупки - ReEntryPips`, для шортов — рост bid выше `максимальная_цена_продажи + ReEntryPips`. Обе стороны котировки берутся из цены закрытия одной и той же свечи, поэтому в этом порте оба сравнения выполняются с одной и той же ценой.
4. **Фиксация прибыли.** Ордер с наибольшим объёмом играет роль «триггера». Когда его прибыль превышает `TakeProfitPips` (65 пунктов) либо цена достигает буферной цели, отстоящей от этого входа на `TakeProfitPips + ExtraTakeProfitPips` пунктов, весь соответствующий блок позиций закрывается одной рыночной заявкой, а лестница очищается.
5. **Контроль маржи.** Перед отправкой нового ордера стратегия проверяет, что свободная маржа портфеля — его текущая стоимость за вычетом сообщённой комиссии — выше порога `Balance × MinimumFreeMarginRatio` (по умолчанию 0.5). Проверка охватывает обе лестницы и каждый вход на них, включая самый первый. Нулевое значение коэффициента отключает её; то же происходит, если портфель вообще не сообщает стоимости — в обоих случаях проверка просто пропускается, и стратегия работает с фиксированными объёмами, как и исходный советник.

## Параметры

| Параметр | Описание |
|----------|----------|
| `TakeProfitPips` | Порог прибыли в пунктах для самого крупного ордера. При превышении закрываются все позиции данного направления. |
| `ReEntryPips` | Минимальное расстояние в пунктах между лучшей ценой входа и текущей ценой, необходимое для следующего усреднения. |
| `InitialVolume` | Базовый объём первой заявки в каждой сетке; последующие ордера удваивают максимальный активный объём. |
| `MinimumFreeMarginRatio` | Минимально допустимое отношение свободной маржи к балансу. При значении 0 проверка отключается. По умолчанию 0.5. |
| `ExtraTakeProfitPips` | Дополнительное расстояние в пунктах, прибавляемое к `TakeProfitPips` при расчёте буферной цели выхода. По умолчанию 25. |
| `CandleType` | Серия свечей, на которую подписывается стратегия. По умолчанию: таймфрейм 1 минута. |

## Особенности реализации

- Пункт (pip) — это не «сырой» шаг цены. На первой обработанной завершённой свече стратегия принимает один пункт равным одной десятитысячной от цены котировки, ограничивает его снизу шагом цены инструмента (чтобы пункт не оказался мельче, чем инструмент реально торгуется) и далее удерживает это значение до конца прогона, чтобы сетка не «плыла» сама под собой. Так воспроизводится форекс-соглашение, под которое писался советник (0.0001 для EURUSD при 1.10, 0.01 для USDJPY при 150), и расстояния остаются осмысленными на инструменте с пятизначной ценой, где «сырой» шаг 0.01 давал бы срабатывание цели в 65 пунктов практически на каждой свече. Если инструмент не сообщает шаг цены, пункт задаётся одной только долей от цены.
- Стратегия работает по завершённым свечам, а не по Level1-котировкам. Она подписывается на серию `CandleType` (по умолчанию таймфрейм 1 минута) и игнорирует все ещё не завершённые свечи. В поставляемой истории нет стакана, поэтому цена закрытия завершённой свечи выступает одновременно и как bid, и как ask. Реализации на C# и на Python подписываются совершенно одинаково.
- Запись в лестницу делается в момент отправки ордера, а не при его исполнении: при открытии в список добавляются цена закрытия свечи и запрошенный объём, а при закрытии отправляется одна рыночная заявка на весь объём лестницы и список очищается. Никакого словаря «ордер → назначение» не ведётся и обработчик исполнений не используется: в этом эмуляторе исполнение приходит синхронно внутри регистрации ордера, ещё до того, как ордер можно было бы записать в такой словарь.
- Каждая запись лестницы сохраняется в обычном списке (цена + объём) вместо обращения к накопительной статистике, что позволяет вычислять максимальный лот и его цену входа, как в оригинальном коде.
- Дополнительный буфер в пунктах, который MQL-версия добавляла к каждому тейк-профиту, вынесен в параметр `ExtraTakeProfitPips` (по умолчанию 25 пунктов) и сохранён как альтернативное условие выхода.

> Реализации доступны на C# и Python.
